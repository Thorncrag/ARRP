# Scoring Standard

A project score is a provisional, reproducible planning value under one adopted
rubric. It is not a measure of the underlying problem's importance and must not
substitute for qualitative findings.

## Required discipline

- State the rubric version, component weights, fixed-zero rules, penalties,
  bands, and evidence standard.
- Award credit only for support present in the current canonical record.
- Apply the same rule across records and political implications.
- When two reasonable reviewers could differ, use the lower supported value and
  explain the uncertainty.
- Repetition alone does not increase quality. A score rises only when the
  record improves under the rubric.
- Display component values, penalties, total, band, review date, and unresolved
  limitations together.
- Keep scoring maturity separate from workflow action, monitoring, and
  publication authorization.

## Change control

Changing a formula, component, weight, penalty, threshold, fixed-zero rule, or
band is a rubric change, not an ordinary record correction. It requires human
approval, a project-level Change Audit, versioning, impact identification, and
recalculation or explicit treatment of every affected score. Never change a
rubric to engineer a desired record or portfolio result.

Each project keeps its exact adopted weights and thresholds in the
project-configuration layer. ARRP's current configuration is
[`../../project/profile/scoring-rubric.md`](../../project/profile/scoring-rubric.md).
