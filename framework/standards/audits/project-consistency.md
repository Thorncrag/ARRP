# Project Consistency Audits

## Authority, Loading, and Dependencies

**Authority.** This module governs the reusable scope, safeguards, deterministic
baseline, and closeout principles of a non-tier, non-scoring Project
Consistency Audit.

**Load when.** Load it for a project-wide structural or integration review,
when interpreting a project-consistency checker, when a Change Audit begins
with project-level consistency, or when a recurring integrity defect may become
a deterministic validation rule.

**Dependencies.** Load the [Framework kernel](../../FRAMEWORK.md) and
[Audit Core](core.md). Load [Change Audits](change-audits.md) when a finding
arises from or affects a governing change. Load the project's hosted-platform
workflow and integrity-bot runbook when hosted state or a particular runtime is
in scope.

## Project Consistency Audit

A Project Consistency Audit is a non-tier, non-scoring review of cross-project
structure and integration. It may check and mechanically correct file paths,
front matter, identifier alignment, heading levels, required-section order,
navigation, registries, source numbering, audit-history nomenclature,
public-site boundaries, internal project links, and drift between an
authoritative project record and hosted workflow fields. It does not count as
an issue-quality audit run.

The configured deterministic checker is a required floor, not an exhaustive
ceiling or substitute for judgment. The auditor must investigate or route every
reported finding and follow credible signs of inconsistency, ambiguity, stale
rules, weak cross-references, reader-comprehension problems, implementation
defects, or logical conflicts outside the encoded scope. A clean result means
only that the configured checks found no defect.

Mechanically correct convention-governed or already-supported defects. Route
legal, evidentiary, fiscal, remedial, lifecycle, or scoring judgments to the
applicable proposal-specific process. When a verified recurring defect can be
detected objectively, improve the existing checker or test suite; when the
lesson is interpretive, incorporate it concisely in the governing authority
that owns the rule.

Do not create a cumulative ledger merely for the pass. Preserve active
continuation state while work is unfinished, the user-facing closeout,
committed change history, and any configured replaceable current report or
bounded runtime history.

A Project Consistency Audit may not alter an issue's diagnosis, evidence
evaluation, remedy, legislative substance, lifecycle status, or score merely
to make records appear uniform. It may correct a demonstrable transcription or
synchronization error to the existing authority. Any finding requiring legal,
evidentiary, fiscal, remedial, or scoring judgment belongs in a
proposal-specific Change Audit or the next appropriate issue-quality audit.
